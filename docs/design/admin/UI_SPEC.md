# PC 管理端开发设计规范

版本：1；日期：2026-09-19；选定方向：温润经营台。

## 1. 视觉目标与约束

浅鼠尾草色导航、暖白工作区、墨绿色操作强调、清晰分隔线。页面优先服务订单处理和数据阅读。
经营分析使用选定原图；工作台、订单中心、商品编辑延续同一套布局与组件。

组件库固定 antdv-next。用 ConfigProvider 统一主题，保留组件原有焦点、键盘和表单行为；应用布局
使用普通 CSS 布局，不逐页覆盖组件内部 class。当前不实现暗色模式、皮肤选择、标签页工作区或多店切换。

## 2. 主题、字体与密度

完整数值见 [theme.tokens.json](theme.tokens.json)。以下为实现基线，不从生成图中反推模糊色值。

| 用途 | 值 | 使用范围 |
| --- | --- | --- |
| 品牌主色 | #265E49 | 主要按钮、选中链接、主图表曲线 |
| 侧栏底色 | #EDF1E9 | 导航区域 |
| 选中导航背景／文字 | #D9E6DA / #1F503C | 当前路由；增加左侧 3px 标记 |
| 页面底色／内容表面 | #F7F7F2 / #FFFFFF | 页面留白、表格及表单 |
| 主文字／次文字 | #202820 / #5F6B63 | 正文、标签、辅助说明 |
| 输入边框／分隔线 | #C9D1CA / #E1E6DF | 控件边界、行与区域分隔 |
| 成功／处理中／危险 | #2F6B49 / #986511 / #B53B3B | 始终配文字，不只依赖颜色 |

正文 14px / 22px；表单标签 14px；辅助说明 13px / 20px；区块标题 18px / 28px；页面标题
28px / 40px；关键指标 32px / 40px。数字使用等宽数字特性，金额右对齐。正文使用系统中文无衬线
字体栈；仅 HAN MENU 字标使用衬线字体，副标题统一「商家管理」。不增加外部字体下载依赖。

控件默认高 36px、圆角 6px；主要确认弹窗按钮可保持相同高度。图标 16—18px，图标按钮点击区域至少
32 × 32px。使用组件库配套图标，图标只辅助文字；只有折叠菜单、复制、关闭等固定操作使用纯图标按钮。
选中项不靠阴影区分；常规内容区不加浮动投影，浮层沿用组件库弹层阴影。

`antdvTheme` 对应 ConfigProvider.theme；`layout/typography/semanticStatus/chart/motion` 为应用自有
设计参数，不可整份 JSON 直接传给 ConfigProvider。使用默认浅色算法，通过 token 和 Menu 组件变量
定制；首版不引入另一套 CSS 框架。弹窗、消息、通知必须在同一主题上下文内，通过 App 容器或上下文
方法调用，避免静态实例丢失主题。参数已对照 antdv-next 官方主题文档及类型核对；建工程时仍需以锁定
版本完成 TypeScript 与渲染验证，本轮未声称完成组件库运行验收。

## 3. 应用布局与响应式

| 区域 | 规格 |
| --- | --- |
| 设计基准 | 1440 × 1024 CSS px；验收 1366 × 768、1440 × 900、1920 × 1080 |
| 左侧导航 | 208px，固定；折叠后 72px；自身可滚动，底部账号区固定 |
| 顶栏 | 64px；左面包屑，右门店名称／状态、通知入口、头像 |
| 页面留白 | 通常 32px；窄桌面 24px；内容最大宽度 1600px，超出时居中 |
| 内容间距 | 区块 32px，表单行 24px，行内控件 12px，紧密图标与文字 8px |
| 表格 | 普通行最小 56px；资金／审计可 48px；表头约 44px |
| 订单详情 | 并排区固定 560px，其余宽度给列表，间隔 24px |
| 通用抽屉／确认弹窗 | 560px / 480px；窄屏上限 viewport − 32px |
| 编辑表单 | 最大 1120px；主字段约 2/3，图片区约 1/3；标签基准宽 104px |
| 底部操作区 | 72px；保留等高内容占位，不能遮挡最后一项字段 |

- ≥1366px：展开侧栏；订单选择后使用列表＋右侧详情；未选择时列表占满宽度。
- 1024—1365px：默认折叠侧栏；订单详情使用 560px Drawer；表格保持可读列宽，必要时区内横向滚动。
- <1024px：导航改为可打开的 Drawer，筛选换行，详情抽屉取屏宽减 32px；只保证可访问和不遮挡，不按移动端重做业务。
- 订单左右区可独立滚动，操作区固定在详情底部；列表分页始终可达。其他页面主内容自然滚动，表头按需要吸顶。
- 商品编辑在可用内容宽度不足 900px 时把图片区移到基本信息之后，标签改到控件上方。
- 浏览器缩放到 200% 时，筛选、确认弹窗及主要操作不能被裁掉；允许表格横向滚动。

顶栏店名来自公开 storefront；营业状态来自 storefront 或工作台。STAFF 不请求管理员 shop 资源。
门店读取失败显示「门店状态暂不可用」，不猜测为营业中。店名没有下拉箭头；管理员从门店设置修改营业状态。
头像与侧栏账号菜单提供「我的账号」「退出登录」。首屏读取 /me 后再显示对应角色菜单，避免管理员入口短暂闪现。

订单 UUID、状态、日期和页码可用于导航；个人资料筛选保留在当前内存即可。

## 5. 公共组件与交互契约

| 公共部件 | antdv-next / 实现方式 | 行为 |
| --- | --- | --- |
| 应用布局 | Layout、Menu、Breadcrumb、Dropdown | 固定导航与角色过滤，不在业务页重复创建连接或会话 |
| 页面标题 | 普通布局＋Typography＋Button | 标题、必要说明、一项主要动作；避免每页欢迎词 |
| 查询栏 | Form、Input、Select、DatePicker.RangePicker | 表单草稿与已应用条件分离；查询后回到第 1 页 |
| 资源表格 | Table、Pagination、Tag | 服务端分页；金额右对齐，日期、UUID 可复制 |
| 状态标签 | Tag＋固定状态映射 | 文字与颜色一致；不让页面自由拼接标签 |
| 详情／编辑 | Drawer、Descriptions、Form | 关闭未保存表单先提示；焦点回到打开它的控件 |
| 业务确认 | Modal＋App 上下文 | 显示对象和影响，提交中禁止重复确认，失败保留上下文 |
| 页面状态 | Skeleton、Empty、Alert、Result | 首次加载、无数据、筛选无结果、失败与无权限分开 |
| 文件选择 | Upload＋独立上传状态 | 上传成功得到 imageId 后才允许提交关联；失败可重选或重试 |
| 图表 | ECharts | 统一颜色／坐标轴，容器 resize；销毁页面时释放实例 |
| 标识展示 | 自有 IdText | 默认前 8 位…后 4 位；悬停与复制为完整 UUID；不能用缩略值发请求 |
| 冲突提示 | Alert＋重新读取按钮 | 保留草稿，说明数据已变化；重新读取后由用户检查再提交 |

### 查询与分页

默认每页 20，通用选项 20／50。员工和目录后端上限虽为 100，首版也用 20／50；通知不使用数字分页。
前端页码从 1 展示，HTTP page = UI page − 1。修改任意已应用筛选时回第 1 页；重置清空全部可选条件。
删除最后一行导致当前页为空时回到上一页重查。金额、手机号、日期不进行仅当前页的“全量筛选”。
没有排序接口时不显示可排序列头；保持后端固定排序。表格刷新不重置选中详情，不覆盖已修改的表单。
UUID／完整手机号格式错误先在输入旁提示；空白筛选规范化后不发送。复制操作显示短暂「已复制」。

请求需取消或丢弃过期响应，快速切换详情不能把上一个订单内容填入新订单。修改成功依据返回资源更新版本；
返回 204 的用例重新读取资源。不要假定每次提交一定 version + 1。

### 通用状态

| 状态 | 表现与文案 | 动作 |
| --- | --- | --- |
| 首次加载 | 保持结构的骨架屏 | 写按钮不可用 |
| 后台刷新 | 保留上次数据并显示轻量刷新状态 | 刷新失败保留数据，提示“数据更新失败” |
| 数据为空 | “暂无订单／暂无商品” | 仅允许新建的模块提供创建入口 |
| 筛选无结果 | “没有找到符合条件的记录” | 清空筛选 |
| 请求失败 | 页面或区块 Alert | 重试；可展开错误追踪号 |
| 401 | 清理会话、缓存、详情与连接 | 登录后仅恢复安全的目标路径，重新读取数据 |
| 403 | 无权限页面或区块 | 返回工作台，不展示上次用户的敏感内容 |
| 404 | “该资源不存在或已不可访问” | 返回列表 |
| 409 | “数据已被其他操作更新，请重新读取后确认” | 不自动重发写请求；保留输入草稿 |
| 429 | “操作过于频繁，请稍后重试” | 尊重 Retry-After，禁用到期前重复提交 |
| 503 | “服务暂不可用” | 保留安全的页面草稿，允许重试；报表未就绪不能显示成 0 |

确认文字按影响写，例如「拒单并申请全额退款」「停用后该顾客的旧登录状态将失效」。取消、退款命令受理后
使用「已提交，处理中」，只有服务端状态到终态才显示成功完成。网络断开且写请求结果未知时先重查，不直接
重复执行。导航离开编辑页及浏览器关闭均有未保存提示；业务请求不做自动乐观成功。

## 6. 工作台

参照 [细化图](assets/workspace.png)。

从上到下：页面标题／经营日 → 五项当前待办 → 左侧待接列表与右侧今日／门店摘要。
顶部待办点击跳转对应状态订单列表，**默认不带日期范围**；待办是全店当前状态，不能只显示今天订单。
左侧查询 PAID，size=5，列表只含订单编号、创建时刻、总额、查看详情；主按钮「去处理订单」。
右侧今日数量只用 createdToday/completedToday，目录数量只用 workspace 响应，STAFF 也可查看摘要但不出现管理跳转。
首次无待办显示「当前没有待接订单」，仍展示其他状态数量。通知连接状态只表达客户端连接状态，不替代业务数据新鲜度。

工作台不加载经营金额；顶部或页脚的数据时间使用 projection.updatedAt，允许无值时显示“尚未更新”。
“查询于”可用本次读取时间，不能把读取时间冒充投影更新时间。统计不可用时，仍允许直接进入订单中心使用权威订单接口。

## 7. 订单中心与详情

参照 [细化图](assets/orders-detail.png)。

默认无日期限制；状态页签为全部、待接单、待配送、配送中，更多状态列出其余四种。页签不显示未经相同筛选
计算的数量，防止全局待办与筛选结果混淆。基础筛选：完整订单 UUID、创建日期；展开后：顾客 UUID、完整收货电话。
查询的是历史收货电话，不是顾客登录电话。管理查询时间采用左闭右开；日期 D1—D2 转为北京时间 D1 零点至
D2 次日零点对应的 UTC Instant，先按时区计算次日再转 UTC。

列表列：订单编号、创建时间、金额、订单状态、查看详情。并排模式中点击整行或键盘进入可选择，行内详情链接仍保留
可访问名称；不加批量勾选。列表不显示它没有返回的姓名、电话、商品列表、付款时间或退款详情，避免逐行查详情。

详情顺序：编号／状态 → 有事实时间的进度 → 商品及规格快照 → 订单总额 → 收货快照 → 催单／取消退款信息 → 操作栏。
未付款金额叫「订单金额」，已付款可叫「实付金额」。不自行拆出运费、优惠、包装费。套餐支持展开原成交组成快照。
电话默认掩码，授权详情可点「显示完整号码」临时展开；关闭详情后恢复掩码。手机号不进入查询键日志或持久化缓存。

进度只显示已有 createdAt、paidAt、acceptedAt、deliveredAt、completedAt、cancelledAt；无时间不补造。
催单次数和最近时间来自 reminderCount/lastRemindedAt。完整支付、退款流水链接只给 ADMIN，STAFF 仍看订单生命周期。
取消原因按后端固定枚举翻译；拒单确认不显示“原因输入框”，当前命令不接受自由文本原因。

| 订单状态 | 中文／语义色 | 主要操作 | 次要操作 |
| --- | --- | --- | --- |
| UNPAID | 待付款／中性 | 无 | 查看详情；商家不能取消未付款订单 |
| PAID | 待接单／处理中 | 接单 | 拒单并退款；更多中可取消并退款，确认说明两者业务原因不同 |
| ACCEPTED | 待配送／进行中 | 开始配送 | 取消并退款 |
| DELIVERING | 配送中／进行中 | 确认完成 | 无取消或退款操作 |
| COMPLETED | 已完成／成功 | 无 | 查看详情 |
| CANCELLING | 取消处理中／处理中 | 无 | 刷新状态 |
| REFUNDING | 退款处理中／处理中 | 无 | 刷新状态；ADMIN 可查看退款流水 |
| CANCELLED | 已取消／中性 | 无 | 展示真实退款状态，不把所有取消都称为已退款 |

订单退款状态独立显示：NONE=无需退款、PENDING=退款处理中、SUCCEEDED=已退款，以实际枚举为准。
点击写操作前以最新详情版本提交；操作中禁用当前订单所有写按钮。成功后更新详情并使当前列表、workspace、相关财务
缓存失效；若订单离开当前筛选，列表移除但详情仍保留更新后的状态，用户自行关闭。

待办订单、CANCELLING/REFUNDING，以及已取消但 lifecycle.refundStatus=PENDING 的详情在页面可见时可每 15 秒重读，返回页面时重读；写操作期间不抢刷。
409 更新状态提示后收起失效动作；不能因为本地按钮可点就假定服务端会接受。相邻订单并发点击各自维护请求状态。

## 8. 商品与分类

商品管理内使用「菜品／套餐／分类」子页面。菜品与套餐列表只显示实际支持的分类筛选；**不提供商品名称搜索、
上下架筛选或全量批量操作**，这些不是当前接口能力。状态在列中展示。列表列：图片、名称、分类、价格、状态、操作。
图片缺失显示组件图标与“未设置图片”；列表图片 48 × 48，object-fit: cover；详情预览 contain。

新建菜品／套餐进入独立编辑路由。编辑在售商品前明确提示先下架，并由用户确认该单独状态动作；成功重取版本后再进编辑。
不能自动下架、编辑、再上架隐藏成一个按钮。下架失败可能被在售套餐引用，按后端错误提示处理；未提供反向引用查询时
不能编造关联套餐列表。删除要求下架且无引用，服务端仍做最终判断。

### 菜品编辑

参照 [细化图](assets/dish-editor.png)。字段与图片分两列，下方口味组按行编辑，固定底部取消／保存菜品。

| 字段 | 交互／约束 |
| --- | --- |
| 菜品名称 | 必填，1—100 字符 |
| 分类 | 必填，仅 DISH 分类；新建默认选择启用分类；旧停用分类可显示现值，提交与上架遵循服务器约束 |
| 售价 | 必填，0.01—999999.99 元，最多两位小数，不自动四舍五入；使用十进制字符串模式或等价精确输入 |
| 类型 | 只读「菜品」，无类型切换控件 |
| 描述 | 0—1000 字符，可空串，显示真实字数 |
| 图片 | 可选；真实 PNG/JPEG，最大 5MiB，边长 ≤4096、总像素 ≤1600 万；先上传后用 imageId 关联 |
| 口味组 | 0—10 组；组名 1—30 字符、组内选项 1—20 个、每项 1—30 字符；去空白后不能重复 |
| 必选开关 | 控制该口味组是否为顾客必选的单选项；不是“多选规格” |

移除图片只清空 imageId，不声称删除对象存储文件。签名 URL 不作永久资源地址；过期后重新读取，出错时提供刷新图片。
保存成功仍是 OFF_SALE，返回列表或留在编辑页提示“已保存，可返回列表上架”；不显示“保存并上架”。

### 套餐与分类

套餐与菜品共用基本信息，口味区替换为「组成菜品」：分页选择菜品、每项数量 1—99、选择固定口味。
同一菜品只出现一次，1—50 项，不可嵌套套餐，不存在套餐自己的口味组。选择器支持分类＋分页，不能假装有服务端名称搜索。
缺少必选规格时定位行错误；上架检查组成菜品及分类可售性。展示名称可按选中组件的 dishId 有界读取并缓存，不在列表全量逐项请求。

分类列表展示种类、名称、排序号、启用状态、操作。创建时种类确定；编辑仅名称、排序号 0—10000、启用状态。
采用 480px Modal；排序号字段逐项保存，不设计拖拽批量排序。删除／停用的引用冲突用明确文本提示，不自动级联操作。

## 9. 顾客、员工与门店

**顾客列表：**手机号精确匹配、名称字面包含、启用状态、注册日期；列为昵称、手机号掩码、状态、注册时间、详情。
详情用 Drawer，展示 UUID、档案、创建／更新时间、启停用及“查看关联订单”。姓名／电话筛选留在内存。禁止代改资料、
地址、密码或直接创建顾客。停用用确认弹窗，说明旧会话失效、历史订单保留；成功读取返回 enabled/version。
重新启用不提示“恢复登录”，要重新登录。顾客详情的订单跳转传 customerId。

**员工列表：**只提供名称筛选，列为用户名、显示名称、电话、角色、状态、创建时间、操作。没有角色筛选／状态筛选接口时
不做对应控件。新建固定 STAFF：用户名字母开头，3—32 位字母数字下划线；姓名 1—50；电话可空；初始密码 12—64 字符。
编辑不含角色、密码字段；禁止删除员工或管理员替别人重置密码。管理员保护约束以服务端为准，在管理员行不展示不支持的停用动作。
员工状态输入为 ACTIVE/DISABLED，顾客为 enabled 布尔值，不混用。

**门店设置：**单店资料表单 name/phone/address，名称 ≤100，电话 ≤16，地址 ≤300；营业状态独立区显示“开店／打烊”。
资料保存用 PUT，状态用 PATCH，各带最新版本。未完善联系电话、地址不可开店；营业时不可清空联系资料。
不添加营业时间段、地图配送范围、运费、起送价等当前没有的字段。状态操作成功后刷新顶栏、workspace 和本页。

## 10. 支付、退款、经营分析

**资金列表：**支付／退款分页分开路由，均可按状态、订单 UUID、顾客 UUID、原支付 UUID、创建日期过滤。
默认只展示主过滤项状态、订单号、日期，其余在“更多筛选”。列为流水 UUID、订单 UUID、金额、状态、创建时间、详情。
详情 Drawer 展示原支付／订单引用、渠道交易号、确认时间、关闭意图及固定失败分类；暂无值用“—”。

支付 PENDING=待支付、SUCCEEDED=支付成功、CLOSED=已关闭；退款 PENDING=退款处理中、SUCCEEDED=退款成功。
“刷新”只重新 GET 本地事实，不宣称触发支付宝主动查单；没有财务补单、手工成功、独立退款或任意金额退款按钮。
未终结交易打开详情时可每 15 秒读取最新服务器状态。客户端只格式化金额，不重新计算订单应付额。

**经营分析：**以 [选定图](assets/reports-selected.png) 为主：日期／下载报表 → 营业额、完成订单、客单价、新增顾客 →
营业额趋势 → 商品销量。日期默认最近 7 个经营日，包含今天，最多 366 天。快捷项最近 7 天、最近 30 天、自定义；
from/to 直接为包含首尾的日期字符串，不能使用订单查询的次日排除转换。

首页只展示一个营业额图，切换到订单或顾客统计时复用同一图表区域，使用真实日账字段。销量默认前 10，最多 100，
没有分页参数时不放任意跳页器。曲线不平滑插值，不增加同比、环比、访客或转化指标；展示投影更新时间，今天数据未完结可说明。
空期真实数据为零时显示 0；503 未就绪显示错误区块。图表和排行来自不同响应，分别保留 projection；跨响应的版本若不同
显示“数据正在同步”，不把它们宣称为同一快照。刷新后仍不一致可继续查看，不阻塞订单履约。

下载按钮使用同日期区间后端 XLSX，下载中禁用，处理 JSON Problem 错误，不能把错误体另存成 .xlsx。
营业额按订单完成日，收退款按确认日，二者不互换。财务对账是独立 /finance/reconciliation 页面，显示三项金额、
待退款数及固定差异计数。当前接口只有差异计数，无差异明细 UUID 列表，不能设计“查看这批差异订单”下钻。
可去流水查询或管理员维护页处理投影，不能通过重建按钮暗示修复真实资金状态。

## 11. 通知与系统维护

通知中心使用游标续载，不用常规 page/totalElements。默认展示“待阅读”，按返回 sequence 从小到大连续呈现。
类型为新订单／催单，内容仅用 orderId、type、occurredAt，不假设含电话、姓名、商品。点击打开订单详情后重新取当前状态。
投递状态仅在管理员诊断区域显示：PENDING 待投递、IN_FLIGHT 投递中、DELIVERED 已投递、EXHAUSTED 重试耗尽。
DELIVERED 不等于员工已读。

读取进度 R → 按 after=R 补查 → 保存实际连续页面及其 nextCursor；实时帧只触发该补查。
后台收到或缓存消息不直接 PUT 已读。用户在通知中心确认「将本页标为已读」时，只确认已呈现的连续页末游标，带 receipt.version。
单条点击可以打开订单，但不能跨越前面未确认消息推进阅读游标；首版不提供独立逐条已读。
历史查看从 after=0 以连续分页加载，可按会话内已加载记录浏览；不能伪造反向分页／任意日期筛选。
不提供“全量未读数量”或一键读到未知最新序号；顶栏铃铛用新消息提示点即可，只有后台补查得到真实新项才点亮。

应用实例只维护一条 WebSocket；重连每次申请新票据，后台失效时关闭。断线显示“通知暂时断开，正在重连”，
采用有上限的退避并用 HTTP 定期补查；首次补查未完成时显示同步中，不显示“没有新消息”。
409 重新读取 receipt；多设备已读前移时合并新的服务端下界，但不能自动确认本设备尚未呈现的消息。退出清空个人缓存与连接。

管理员可从具体通知进入投递轨迹 Drawer，展示最多 100 条 attempts。只有 EXHAUSTED 可重投，提交最新通知版本。
系统维护页聚合两块：通知诊断入口与统计投影状态。通知无状态筛选端点，不提供全店耗尽通知的伪总数／筛选表；
可以从顺序通知流选择，或输入已知消息 UUID 查询 attempts；重投前需从真实通知记录获取版本，不让用户手填版本。

投影区展示 initialized、更新时间、重建时间与计数；技术版本／代际放可展开诊断信息。重建要求确认并提交 version，
处理期间禁止重复提交，保留旧报表可查看。当前不是异步任务接口，不画虚假进度条；读取状态直到结果明确，
不能仅凭网络超时判定失败并自动重发重建。

## 12. 安全审计、账号与登录

审计列表支持事件、操作者 UUID、目标 UUID、成功／失败、发生日期。列：时刻、固定中文动作、操作者、目标、结果；
空标识显示“—”，不显示不存在的 IP、设备、任意日志正文或业务修改前后差异。以身份安全事件为范围，页面副标题明确说明。
只读、不可删除、不可编辑；无审计导出接口则不放导出按钮。

我的账号展示 /me 的用户名、姓名、角色、标识；改密表单旧密码、新密码、确认新密码。确认字段仅前端校验，
HTTP 只发送 currentPassword/newPassword；此接口没有 version 参数，不能机械追加资源版本。
改密成功显示“密码已修改，请重新登录”，清理全部本地认证状态并跳转。本人资料不提供不存在的修改接口。

登录页使用同色系背景和约 400px 表单宽度，标题“登录商家管理”，用户名／密码／显示密码／登录按钮。
无注册、微信、短信、找回密码、长期自动登录入口。字段错误在本地显示，认证失败按统一文案，不猜测账号是否存在。
保存会话采用内存＋sessionStorage 的已定方案，不保存密码、不解析 JWT、无刷新令牌接口。退出调用删除当前会话后清理；
若服务器不可达，仍清理本地并说明仅完成本地退出，不能声称服务器已撤销。

## 13. 实现顺序与验收

| 顺序 | 可交付工作 | 完成条件 |
| --- | --- | --- |
| 1 | 主题、应用布局、角色导航、公共页面状态、登录与账号 | 三种桌面尺寸可用；刷新认证恢复，401/403 正确 |
| 2 | 工作台、订单列表／详情／状态动作 | 所有八种订单状态和 409 场景通过，未付款无商家取消入口 |
| 3 | 分类、菜品、套餐、图片、门店 | 下架编辑、引用冲突、图片失败、未保存关闭均有完整反馈 |
| 4 | 员工与顾客 | 不越权、不显示不存在的编辑能力，启停用后会话行为正确 |
| 5 | 通知与恢复 | 乱序／重复帧、掉线、重新登录不丢连续进度，也不误判已读 |
| 6 | 资金、报表、审计与维护 | 日期口径正确，金额无浮点重算，下载和投影异常可处理 |
| 7 | 交互及视觉验收 | 键盘全流程、200% 缩放、空／失败、表单保护及独立构建全部通过 |

上述顺序是每阶段的小闭环，整体仍按 P7_FRONTEND_PLAN 的 PC-0—PC-6 分期；订单可先完成只读布局，
真实接单／履约验收需要基础资料阶段已完成。不得把设计稿中的样例行作为接口失败时的兜底数据。

- 主操作对比度目标 ≥4.5:1；焦点可见；状态始终带文字，图表提供表格或文本数据替代。
- Tab 可进入筛选、表格链接、详情和确认操作；Esc 关闭浮层，未保存时先确认；弹层焦点受控并能返回原按钮。
- 日期输入有可读格式和标签，图标按钮有中文可访问名称；加载、成功及错误通知可被辅助技术获知。
- 长标题、长 UUID、长地址、四位以上计数、大金额、十组口味、五十项套餐均能展开阅读，不能推挤掉保存按钮。
- 绿色主题覆盖下拉、日期选择、Modal、message、notification，避免只有页面本身变色。
- 在页面可见时按需更新，输入中的筛选和长表单不被轮询覆盖；退出和切换账号无前用户数据残留。
