## 使用顺序

1. 用 UI_SPEC 与 theme.tokens.json 建立应用布局、主题及公共组件。
2. 按 API_MAPPING 实现页面模型；从服务端 OpenAPI 生成类型，字段以契约为准。
3. 对照四张图检查视觉，并用 UI_SPEC 的状态表补齐加载、空、失败、无权限与并发冲突。
4. 按实施清单逐页联调；这些图片是设计稿，没有真实调用接口或经过浏览器交互验收。

## 图稿与规范的关系

图片确定视觉方向与区域关系，精确尺寸、文案和交互以 UI_SPEC 为准。图片文件实际分辨率由生成工具
输出；开发采用 1440 × 1024 CSS 像素基准，不能按图片像素逐项机械测量。

统一品牌副标题为「商家管理」，替换部分图中的「中式美味 用心传递」。菜品类型显示只读文本，
不使用看似可编辑的禁用输入框；表单字数由输入实际计算。图片、通知时间、数量及人物均为演示内容，
不作为应用默认数据。订单分页显示实际返回行数，不照抄图中为展示留白而缩减的示例行数。

原图保留在生成目录；本目录保存副本，便于仓库内评审及开发引用。首版浅色主题，不增加主题切换器。
