# PC-5：经营分析与维护

日期：2026-09-22。本阶段在现有 `admin/` 工程接入 P6 与 P7 前置真实接口，不新增业务接口、支付模拟入口或数据库迁移。仅管理员可访问本阶段页面，前端路由与导航限制和后端当前身份检查同时生效。

## 页面与业务范围

| 页面 | 路由 | 已实现能力 |
| --- | --- | --- |
| 支付流水 | `/finance/payments/:id?` | 状态、订单、顾客、支付UUID与创建日期组合检索，后端分页，详情与关联退款 |
| 退款流水 | `/finance/refunds/:id?` | 状态、订单、顾客、原支付与创建日期检索，详情及原支付／订单跳转 |
| 经营分析 | `/reports` | 经营汇总、营业额／创建订单／新增顾客趋势、日账、销量前10—100、后端XLSX |
| 资金对账 | `/finance/reconciliation` | 实收、已确认退款、净收款、固定差异计数及全店待退款 |
| 安全审计 | `/settings/audit` | 固定安全事件、操作者、目标、成功与否、发生日期及后端分页 |
| 系统维护 | `/settings/maintenance` | 投影状态／重建、通知顺序流、投递尝试、耗尽通知重投 |

订单详情仅给管理员提供财务详情链接；通知中心仅给管理员提供具体通知的投递轨迹入口。普通员工仍可执行订单履约和个人通知阅读。

## 日期、金额与统计口径

流水和审计日期按上海时区转换为 UTC 左闭右开区间：同一天对应上海当天零点至次日零点。报表日期直接提交 `from/to`，包含首尾经营日，默认最近7天，可选最近30天或最多366天的自定义范围。两类协议不混用。

金额、汇总、完成率和客单价均使用服务器字段，前端只格式化两位小数。营业额按订单完成日；创建群组完成率按同一创建日期群组；收退款按各自确认时刻；累计顾客包含起日前注册事实。未确认退款显示“退款处理中”，不视为资金支出。

趋势区复用一个 ECharts 图表，按需加载所需的折线、SVG、网格、提示与无障碍组件，不做平滑插值。容器变化触发resize，卸载dispose。经营日账提供同一批数据的表格视图。

经营汇总、销量及对账分别保留自己的投影元信息。经营汇总与销量的代际／修订不同会提示“数据正在同步”，不宣称跨响应处于同一快照。加载、真实空数据、503不可用各自展示，失败不会变成零金额。

对账正向差异按查询日期区间，反向缺少收／退款事实及待退款按全店当前状态。差异可能重叠、也可能受事件延迟影响。接口只有差异计数，页面不提供不存在的差异明细下钻。

## 下载与会话

XLSX直接使用后端工作簿，统一客户端携带员工Bearer并沿用401撤销、403和RFC9457反馈。下载固定点击时日期，期间禁用重复下载；验证MIME和非空内容，JSON Problem或HTML页面不得保存为XLSX。页面卸载取消请求并释放Blob URL；会话变化后的迟到结果不触发下载。

普通请求15秒超时，报表导出60秒；重建POST为195秒，以覆盖后端最长180秒事务。部署反向代理应匹配此等待边界。其他请求不会因维护功能而全局延长。

## 通知投递诊断

维护页按真实通知流的nextCursor前移，只能返回已经浏览的上一页，不伪造总量和全店耗尽筛选。可按已知UUID只读查询最近最多100条尝试；状态、成功／失败连接数及失败分类来自接口。

从通知流或通知中心进入详情时，记录携带真实sequence和version。重新读取通过已知sequence之前补查一条并核对UUID，取得最新版本；不能让管理员手填版本。仅EXHAUSTED可重投，确认说明重复提醒的可能性及阅读进度不变，成功后显示登记结果，实际投递仍由服务端工作器完成。

409、网络错误与服务器异常阻止直接重复提交，要求显式重读。维护页不PUT个人receipt，不重建通知历史；DELIVERED不代表员工已读。

## 投影重建

显示初始化状态、更新时间、重建时间与订单／顾客／收退款记录数，技术版本、代际、修订在可展开诊断中查看。

重建先展示影响说明并确认，提交当前控制版本；确认及执行期间阻止重复写入与离开页面，会话失效仍可退出并销毁确认框。成功采用服务端返回状态，使报表与工作台缓存失效。旧报表可继续读取，页面不展示虚假进度。

409先刷新版本再确认。网络结果未知时显示“重建结果尚未确认”，不能自动重发；刷新状态发现版本推进可解除阻塞，同版本在最长事务／网络等待窗口内继续阻塞。达到195秒后仍须成功读取状态才可重新确认，不把本地超时直接等同服务器回滚。

## 验证入口与边界

使用 `./scripts/verify.sh` 执行后端、前端静态检查、生成类型一致性、单元测试、生产构建和真实Chromium测试。
所有数据库验收使用既有运行器的 `_test` 数据库与临时schema。订单／付款／退款及耗尽通知测试事实通过仅用于测试的脚本构造，不调用真实支付宝，也不增加应用模拟支付接口。通知重投、投影重建、查询、下载及权限均调用真实后端；仅故障恢复场景注入错误或响应丢失。

实现与视觉参考沿用 `design/admin/UI_SPEC.md` 第10—12节；浏览器截图与布局记录见 `../admin/design-qa-pc5.md`。
ECharts导入与生命周期依据：[按需导入](https://echarts.apache.org/handbook/en/basics/import/)、[容器与销毁](https://echarts.apache.org/handbook/en/concepts/chart-size/)。
